## Резерв і відновлення

Перед очищенням створено локальний коміт **83bed72** з попереднім станом коду,
конфігурацій і документації. Незакомічені й ігноровані дані додатково скопійовано
до `archive/pre_cleanup_20261023/workspace_and_data.zip`.
`inventory.json` поруч містить SHA-256 кожного файла та ZIP. Перевірено CRC ZIP
і кожен запис за SHA-256: 1281 файл, 848933574 байти до стиснення.
ZIP займає 224568582 байти. Це локальна копія на тому самому диску, не off-site backup.

Видалений код можна переглянути через `git show 83bed72:<шлях>` або відновити
вибраний файл через `git restore --source=83bed72 -- <шлях>`.
Великі дані й дампи можна витягнути з ZIP у новий каталог для порівняння;
не розпаковуйте весь резерв поверх робочого проєкту.

## Що передається через Git

- Код, тести, поточні й історичні конфігурації, документація.
- Компактні immutable bundles у `data/edge/`, включно з integrated/hold/system,
  які потрібні для поточного виконання та версійних порівнянь.
- `data/releases/k306_tau025_offline_v1` — перевірений автономний offline-пакет.
- **Один** обраний research run `data/selection/mvp_frozen_core_v1/trial_00003/after`,
  включно з checkpoint, graph і report (разом близько 1 МБ).
- Вибрані підсумки frozen-core, module-boundaries, sensor-handover і transport-v3.
  Повні траси цих серій не додаються.

Нові `data/diagnostics/`, `data/selection/`, `data/releases/` ігноруються за
замовчуванням. Вибрані файли додано явно; ігнорування не припиняє відстеження
вже наявних у Git історичних даних. Старі tracked результати поки не видалено.
Для майбутнього додавання використовуйте точні перевірені шляхи, не масовий
`git add -f data`.

Повне навчання з нуля потребує окремих source/dataset артефактів, які не входять
до цього малого комплекту. Команди історичних дослідів можуть потребувати їх.
Для exact before/after порівняння `validate_module_refactor` також потрібні
локальні JSONL із `transport_loop_v3`; поточну фізичну перевірку можна виконати
незалежно через `validate_transport_loop`.

## Навмисно залишено

`generator/`, навчання/відбір, дослідницькі probes, memory, OU/Levy, Isaac backend,
сумісні API й усі перевірки активних контролерів. Відсутність використання
в одному runtime не доводить непотрібність для наукового проєкту.
Пакети не перейменовували; ваги й sealed bundles не переписували.

## Перевірка очищеного комплекту

Результати: [cleanup_validation.json](cleanup_validation.json).
Окремий каталог `archive/cleanup_validation_20261023/checkout` зібрано тільки
з Git index через `checkout-index` з `core.autocrlf=true`. Локальні datasets,
необрані checkpoints і JSONL не копіювалися. Використано наявне середовище
Windows Python 3.12 — це не свіже встановлення залежностей і не Linux/Pi.

- **800 passed за 70.34 с** у цій окремій копії.
- Усі **6** NumPy bundles пройшли checksum validation після checkout.
- Поточний `build_system(v3)` і точний research checkpoint завантажено.
- Автономний release: **40** прийнятих команд, дві сесії, watchdog і відхилення
  старої сесії; новий release також успішно зібрано з цієї копії.
- **14/14** фізичних сценаріїв пройдено. Усі physics rows, receiver/link events
  і командні значення точно збігаються з `transport_loop_v3`. Із порівняння
  виключено лише `manifest_sha256`, залежний від абсолютного шляху виконання.
- Ваги, вихідний код активних контролерів і sealed пакети не змінені.
- Нові навігаційні посилання перевірено. Whitespace check пройдено з
  `cr-at-eol`: CRLF всередині старих sealed артефактів збережені навмисно.
