# Кодування дальності завершення маневру: реалізація та парне навчання

Дата: 05.11.2026. Продовження [перевірки вчителя](TEACHER_CLOSED_LOOP_UK.md).

**Статус:** неузгодженість сенсорного кодування виправлена в окремій дослідній версії, перевірені checkpoint/export/NumPy та сумісність старих пакетів. Парне донавчання не дало придатної польотної моделі: обидві гілки втратили крейсерський рух. Активний пакет і його ваги не замінені.

## 1. Новий контракт

Старий `proximity-v1` збережено без зміни чисел:

$$e_{old}(d)=\max(0,1-d/0.8).$$

Новий **`proximity-release-v1`**:

$$e_{release}(d)=\max(0,1-d/1.0).$$

Тепер 0.85 м дає 0.15, 0.95 м — 0.05, а 1.05 м — 0. Поріг 1.0 м обрано як фіксовану інженерну межу із запасом над умовою завершення маневру вчителя 0.95 м; це не результат оптимізації. Поріг APF-загрози вчителя залишається **0.8 м**. Змінилася обробка наявних ToF-каналів, а не фізичний сенсор, кількість входів чи формат пакета ESP32.

Ця формула змінює також величину сигналу на відстанях < 0.8 м. Тому парний дослід перевіряє ефект нового кодування загалом, а не лише додавання смуги 0.8–0.95 м.

У `simulation/policy.py` додано нову назву та її параметри в архітектурний контракт. `edge/export_numpy.py` переносить назву і поріг у метадані. `edge/runtime.py` приймає тільки визначені пари «назва → поріг»: стару → 0.8, нову → 1.0. Помилкова пара відхиляється навіть після перерахунку контрольної суми метаданих.

Звичайне `load_state_dict` не дозволяє завантажити старий checkpoint у модель з новою семантикою. Для досліду є явний `migrate_release_encoding()` в `optimizer/release_encoding.py`: він копіює модель, перевіряє старий контракт, зберігає всі числові параметри та змінює лише оголошену семантику входів. Новий checkpoint записується окремо з цією історією перенесення. Це початкова точка донавчання, не твердження, що старі ваги вже придатні до нового кодування.

## 2. Чому знадобився завантажувач зафіксованого runtime

Старі пакети містять власний `runtime.py` і його SHA-256. Після додавання нового кодування виконувати їх оновленим repository-runtime, ігноруючи перевірку, було б неправильно.

`edge/pinned_system.py` зберігає цю перевірку:

- якщо runtime збігається з поточним, використовується штатний `build_system`;
- якщо відрізняється лише runtime, завантажується **перевірений код із самого пакета**;
- `system`, `flight_bridge`, `sensors`, `altitude_control`, `xy_coordinator` мають збігатися з поточними за хешами, інакше адаптер відмовляє;
- спільні типи сенсорів і lease не дублюються;
- код читається із перевіреного `.py`, без читання чи створення `.pyc` усередині пакета.

Це вузька сумісність для довірених локальних пакетів, не універсальний завантажувач будь-яких історичних контрактів і не sandbox для стороннього коду. Перевірки SHA-256 гарантують цілісність, не походження пакета.

На цей адаптер переведено `demo/runner.py` та `edge/pi_hardware_adapter.py`. Строгий `edge.system.build_system()` не послаблено: пряма спроба виконати іншим кодом старий пакет усе ще відхиляється. Старі ізольовані releases залишаються автономними. Чисельна історична траєкторія `068fe108` і network PWM перевірені на **точний збіг** із попереднім записом після зміни способу завантаження.

## 3. Зафіксований парний експеримент

Дві гілки починаються зі збереженої початкової моделі `data/selection/mvp_frozen_core_v1/trial_00003/after`, а не з невдалого plastic-кандидата:

| Параметр | Обидві гілки |
|---|---|
| Дані | Уже підготовлений `output/balanced_maneuver_v1/train.pt`, 104 повні епізоди |
| Учитель | v5/1530, мітки не перегенеровано |
| Навчання | 10 епох, 130 оновлень, batch 8, lr 0.001, seed 42, CPU |
| Loss | channel-v4, yaw balance 0.7 |
| Заморожено | W, tau, A; нульові bias, зафіксовані neutral_origin |
| Навчальні параметри | Сенсорні масштаби, дозволені W_in і DN-декодер |
| Відмінність | `proximity-v1` проти `proximity-release-v1` |

Умови записано перед навчанням у `output/release_encoding_v1/protocol.json`. Обидві гілки мають оцінку до навчання у `*_initial.json`. Нові геометрії, нова конектома, зміни координатора та додаткові довгі історії пам'яті не вводилися.

Після першої гілки перевірка ізольованого експорту зупинилася через недоступний системний TEMP Windows. Навчений checkpoint уже був збережений. Продовження виконано через `--resume` з TEMP у проєкті: готову гілку не перенавчали. `resume.json` фіксує зміну runner та source-only loader, а також початковий hash runner. Файли даних, активний пакет і початковий checkpoint залишилися незмінними.

У новій гілці не пройдено широкий правий стимул на 0.70 м: Yaw 1260.31 проти цілі 1380, відхилення 119.69 PWM при допуску 100. Напрямок правильний, але критерій амплітуди порушений. Його не приховуємо й не змінюємо після результату.

Пара 0.85/1.05 м більше не є однаковим входом. Однак це лише знімає інформаційну заборону на розрізнення, а не забезпечує правильне навчання. Після маневру нова модель у кінці контрольної пари дає приблизно:

- 0.85 м: Pitch 1454.90, Yaw 1492.06;
- 1.05 м: Pitch 1494.79, Yaw 1500.02.

Цілі вчителя — відповідно `(1500, 1620)` та `(1530, 1500)`. Отже, розрізнення з'явилося, але бажаний маневр не засвоєний. Не можна називати це виправленою поведінкою.

## 5. Фізичні прогони: обидві гілки майже не рухаються

Вісім прогонів через незмінний інтегрований контур, чотири ті самі кімнати, 45 с кожний. У всіх є фактичний AUTO і немає контактів, але:

| Кімната | Відстань: старе / нове кодування, м | Середня швидкість AUTO: старе / нове, м/с |
|---|---|---|
| 068fe108 | 0.129 / 0.150 | 0.00291 / 0.00336 |
| 89d81a9f | 0.154 / 0.170 | 0.00346 / 0.00382 |
| 9d5431c1 | 0.182 / 0.216 | 0.00410 / 0.00485 |
| b0a9f212 | 0.198 / 0.222 | 0.00446 / 0.00498 |

**Це провал рухової задачі, а не 8 успішних уникнень.** У початкової моделі нейтральний крейсерський Pitch був 1526.01. Після цього донавчання він нижче 1500 в обох гілках; штатний anti-rollback не дає цій команді перетворитися на стале відступання, але руху вперед теж немає. Прохід простих сцен сам по собі цього не виключає.

У цій спрощеній парній постановці не було явного доданка збереження крейсерського руху, який уже використовувався в попередніх дослідах. Втрата руху була відомим ризиком. Відсутність такого контролю обмежила корисність фізичного порівняння — це недолік постановки експерименту, а не свідчення, що нове кодування погіршило навігацію. Моделі практично не доїхали до ситуацій, заради яких вводилася нова інформація.

## 6. Висновок і наступна межа роботи

Інженерну частину можна використовувати далі: версія кодування, захист контракту, експорт і сумісність працюють. **Жоден новий checkpoint не прийнято як робочий.**

Наступне навчальне порівняння має зберігати крейсерський рух як явну ціль і перевіряти його до запуску всієї серії кімнат. Розумний обмежений варіант — повернути вже наявну ціль крейсерського руху в обидві гілки без одночасного повернення довгих суперечливих допоміжних історій. До нового фізичного запуску перевіряти, що модель здатна розпочати й підтримувати рух у чистому просторі. У цьому звіті таке додаткове навчання ще не виконувалося.

Поріг нового кодування, учителя чи координатор після отримання невдалих результатів не підлаштовували. Дослід не доводить достатності замороженого ядра для вивчення всієї поведінки.

## 7. Перевірки і відтворення

- PyTorch/NumPy в ізольованому bundle: 400 кроків, чотири режими контуру для кожної гілки. Максимальна різниця network PWM **0.0001221**, розбіжностей причин втручання координатора — **0**.
- Checkpoint roundtrip перевірено.
- Старий baseline через зафіксований runtime відтворився точно.
- Активний пакет, його конфігурація та вихідні дані збережені за SHA-256.
- Нові адресні тести перевіряють смугу дальності, відхилення несумісних checkpoint, паритет експорту, заборону довільного порога й історичну збірку.
- Перший повний запуск мав 1204 успішні тести та 18 відмов: частина виявила стару точку збірки hardware adapter, решта — недоступний UDP loopback у обмеженому середовищі. Після виправлення точки збірки й запуску локальних мережевих тестів у придатному середовищі **повний повтор: 1222 passed за 156.74 с**. Це програмні тести; реальне обладнання не залучалося.

Код досліду: `optimizer/release_encoding.py`. Звіт без повторного навчання: `evaluate/report_release_encoding.py`. Результати: `output/release_encoding_v1`, включно з `protocol.json`, `resume.json`, `comparison.json`, `flights.json`, `assessment.json`, `validation.json`, `pytest-final.txt` і пакетами обох гілок.

```powershell
# За потреби локальний TEMP, якщо системна тимчасова папка недоступна:
New-Item -ItemType Directory -Force .runtime-tmp | Out-Null
$env:TEMP = (Resolve-Path .runtime-tmp).Path
$env:TMP = $env:TEMP
.\venv\Scripts\python.exe -m optimizer.release_encoding --out output/release_encoding_repeat
.\venv\Scripts\python.exe -m evaluate.report_release_encoding output/release_encoding_v1
```

`--resume` призначений для відновлення після збереженого експорту, перед польотною серією; він не є універсальним менеджером відновлення з довільного перерваного кроку. Успішно завершений каталог не перезапускати й не перезаписувати.
