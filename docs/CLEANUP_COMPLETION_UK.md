## Класифікація того, що залишилося

Категорія означає роль, а не обіцянку, що кожна історична команда запускається
без локальних dataset/checkpoint файлів.

| Група | Категорія та причина збереження |
|---|---|
| `edge/` runtime, sensors, bridge, system, receiver, transport, release | Активна інтеграція та її offline інструменти |
| Спільні XY/Altitude контролери у `simulation/` і aliases в `edge/` | Активний контур; aliases є API сумісності, не дублікати алгоритмів |
| `core/`, `simulation/policy.py`, `artifacts/` | Активна математична модель й перевірка походження артефактів |
| Решта `simulation/`, `assets/` | Фізика, сенсори, сцени, schedule, fallback та допоміжні модулі перевірки. Isaac backend і URDF — опціональний шлях, не вимога NumPy inference |
| `generator/`, `optimizer/`, `bc_test.py` | Дослідницький цикл: acquisition, редукція, вчитель, навчання, probes, відбір. Вибір одного checkpoint не робить цей код зайвим |
| `evaluate/` | Спостереження й інтеграційні експерименти; прямий research rollout і наскрізний transport rollout перевіряють різні контури |
| Python-скрипти в `scripts/` | Відтворення сенсорних та поведінкових дослідів; `probe_filtered783.py` — acquisition probe, а не deployment entrypoint |
| `configs/mvp_runtime_v3.json` | Поточна конфігурація інтеграції |
| `configs/mvp_runtime_v1.json`, `v2.json`, research-конфігурації | Відтворення етапів assembly/handover та дослідів; не альтернативні поточні defaults |
| `configs/cell_mapping.json`, `config.py`, `configs/__init__.py` | Mapping має реальних споживачів; маленькі re-export API залишені для сумісності |
| `tests/`, `test_imports.py`, `pytest.ini`, requirements | Перевірки й середовище; helper-файл без власних тестів не є зайвим |
| `data/edge/k306_tau025_integrated_v1`, offline release, обраний checkpoint | Поточні артефакти MVP; однакові ваги в різних bundles не роблять їхні контракти/код однаковими |
| Решта 5 `data/edge/` bundles | Відтворення NumPy parity, behaviors, bridge, assembly і sensor-handover; зберігаються незмінними |
| `data/reduced_models/flywire783_filtered_v2`, source manifests, annotations, validation reports | Кандидати та походження даних, включно з відхиленими контрольними варіантами |

| `docs/CODEBASE_*`, audit inventory, датовані звіти `scripts/*.md`, старі integration-плани | Історичні пояснення рішень; актуальний маршрут читання — `docs/README.md` |

Історичні аудити не переносили лише заради нової структури: їхні посилання
та датовані твердження мають залишатися зрозумілими. Спільні контролери також
не перейменовували: це спричинило б перебудову sealed пакетів без користі MVP.

## Відновлення та перевірка

Стан перед цим проходом: `cec0cd489a4a8dda641b35849ea48d22b8f0edfc`.
Будь-який прибраний файл можна прочитати через `git show <commit>:<path>`.
Додатково всі 37 файлів перед переміщенням записано у локальний
`archive/residual_cleanup_20261023/retired_files.zip`; перевірені CRC і SHA-256
кожного запису. `inventory.json` поруч містить оригінальні шляхи та хеші.
Розпаковуйте потрібні файли в окремий каталог, не поверх поточних bundles.

Результати перевірки цієї серії — [cleanup_completion_validation.json](cleanup_completion_validation.json).
Архів локальний; у Git залишаються попередній коміт і цей звіт.

- Окрема копія лише з Git index, з `core.autocrlf=true`: **800 passed за 80.55 с**,
  без пропущених тестів. Видалений порожній test-файл не зменшив кількість cases.
- Усі **6** NumPy bundles пройшли checksum validation; поточна система v3
  та точний research checkpoint успішно завантажені.
- Offline release: **40** прийнятих команд, дві сесії, watchdog і відхилення
  старої сесії; заборонені залежності не завантажені.
- **402** збережені файли залишились побайтово незмінними. Змінено лише чотири
  наявні текстові файли: `.gitignore` та три документи; додано цей звіт і JSON.
- Перевірено 13 відносних посилань у поточній навігації та звіті.

Використано наявний Windows Python 3.12 venv, не свіже встановлення чи Pi.
Попередню серію 14 фізичних сценаріїв не перезапускали: активний код, конфігурації,
ваги й sealed пакети незмінні; старі результати не подаються як нові вимірювання.

Погоджений прохід очищення завершено після перевірок. Збережений дослідницький
код — свідомий склад проєкту, а не черга обов'язкових видалень перед GitHub.
Апаратна інтеграція та перевірка реального польоту залишаються окремою роботою.
