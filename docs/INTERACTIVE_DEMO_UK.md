## Запуск

У корені Chong-Fly, у вже встановленому середовищі проєкту:

```powershell
.\venv\Scripts\python.exe -m demo
```

Відкрити **http://127.0.0.1:8765/**. За зайнятого порту: `--port 8766`.
Сервер слухає лише loopback. Для завершення — Ctrl+C у вікні запуску.
Усі HTML/CSS/JS та записи локальні; CDN, завантаження assets або нових
залежностей немає. UI використовує Canvas із проєкцією тривимірної геометрії,
а не зовнішній 3D engine. Рекомендовано desktop-екран; на вузькому екрані
панелі переходять у вертикальний порядок.

На цій машині фінальна перевірка виконувалася на порту 8766.

## Поточний інтерфейс · 04.11.2026

### Контакт біля кутів · виправлення 04.11.2026

На екрані показана сфера R=0,20 м, а старий detector
`simulation/collisions.py` розширює кожну вісь боксу на R. Такий broad phase
має квадратні/кубічні кути, тому навколо кута спрацьовує раніше, ніж сфера
торкнеться реальної поверхні. Це невідповідність показаної області та
консервативного detector, а не помилка малювання координат.

Зафіксований користувацький випадок: seed 2209320175, t=11,144 с,
центр `[-0.1855552047, -1.3913556337, 0.9972406626]`, найближча точка боксу
`[0.0066042225, -1.59, 0.9972406626]`. Відстань до поверхні 0,276378 м,
зазор за сферою — **0,076378 м**, хоча старий detector повертав collision=box.
Початковий прогін: `output/interactive_demo/contact_before_run.json.gz`.

У `demo/contacts.py` додана narrow phase для сфери на всій траєкторії за 4 мс.
Для боксу мінімум відстані до відрізка обчислюється за точними квадратичними
ділянками між перетинами slab-площин. Для скінченного циліндра — мінімум
опуклої функції квадрата відстані; похідна локалізує його бісекцією.
Це враховує грані, ребра, кути й закруглені сферою краї торців циліндрів.
Швидкий проліт через тонкий об'єкт фіксується й при чистих кінцях кроку.

Demo-адаптер уточнює тільки `collision_kind`, `clearance_m`, crash/done та
відповідний штраф reward після чинного `env.step`. Інтегратор, позиція,
швидкість, сенсори й контролери не переписані. Invalid state, excessive tilt
та user_closed зберігають припинення. Benchmark-файли
`simulation/collisions.py`, `simulation/drone_env.py` не змінено.

`manifest.contact_model = sphere-sweep-v1` — нові живі прогони.
`expanded-primitives-v1` або відсутність поля — старий conservative контракт.
Канонічні записи залишені на старій моделі, їхні фізичні кадри збігаються точно.
Модель контакту відновлюється під час recompute, тому старий запис не отримує
нових правил мовчки.

Повтор користувацького випадку з тими самими командами:

```powershell
.\venv\Scripts\python.exe -m demo.probe_contact output/interactive_demo/contact_before_run.json.gz
```

### Основні дії

Вкладка **Наживо**, керування **Автономне**, одна кнопка **Старт**.
Окремі банер і кнопка «Запустити МУХУ» видалені. Ручне керування та SHADOW
обираються в одному списку. Початкова сторінка — жива сцена; старт явний.
Налаштування сцени згорнуті над полотном, основні показники й фактичні стани
мережі — праворуч. Детальні ToF, графіки, події та контракт — у розгортаних
панелях. У записах повзунок, кадр і швидкість з'являються тільки для replay.
Камера й масштаб — два списки. **Межа контакту** — прапорець під сценою.

Нові живі прогони мають **радіус зіткнення 0,20 м**, діаметр 0,40 м.
Видимий силует бере той самий радіус із manifest і цілком вкладається в нього.
Це схематична модель, не CAD. Маса, мотори, контролери, ваги й admission
не переналаштовувалися. Більше тіло закономірно раніше контактує з перешкодами.
Генератор щільності `demo-room-density-v3` залишає щонайменше **0,48 м**
між bounding footprints; запас понад діаметр — 0,08 м. Для старих записів
збережено їхню геометрію, радіус 0,10 м та генератори v1/v2.

**Тривалість, с**: 1–600, за замовчуванням 180. Значення можна змінювати
під час польоту; воно застосовується після завершення введення. Ліміт має
перевищувати вже минулий simulation time. Подія `duration` записується у input
schedule; `manifest.max_duration_s` — початковий ліміт, snapshot містить чинний.
Час керування/фізики залишається 20/4 мс. Завершений прогін не поновлюється
редагуванням тривалості — потрібен новий старт.

Пауза й втрата фокуса відкликають AUTO. Коли потрібна свіжа сесія, головна
кнопка стає **Новий старт**; вона створює нову сесію та повторно проходить
admission. Ручну паузу можна продовжити без скидання. Клавіші WASD, M, H,
Enter, Space, P та R збережені; введення чисел не є польотною командою.

Перевірки: **1036 passed in 130.39 s**, `output/interactive_demo/ui_full_suite.log`;
після фінального уточнення revision події часу — **67 passed in 32.06 s**,
`ui_final_targeted.log`. Тест справді виконує живий прогін понад 60 с до нового
ліміту 61 с. `ui_trace_parity.json` підтверджує точний збіг фізичних кадрів чотирьох
канонічних записів зі старими трасами. Browser QA підтвердив зміну ліміту
активного прогону до 300 с і окремий live-прогін до 85 с при ліміті 90 с,
ручне керування/паузу/новий AUTO старт, replay seek та детальні графіки.
На вузькому екрані 390 px немає горизонтального переповнення. Знімки:
`output/interactive_demo/screenshots/ui_*.jpg`, підсумок — `ui_browser_qa.json`
у `output/interactive_demo/`. Захищений physics/controller code,
ваги й конфігурація не змінені. Далі наведено історію попередніх перевірок.

не додані. Фізичний radius, dynamics, контролери та admission незмінні.

## Сценарій захисту на 5–7 хвилин

Найкоротший показ ШІ: **Наживо → Автономне → Старт**.
Старт створює обрану сцену за потреби, продовжує час та запитує AUTO.
Мережа обчислюється під час штатного admission; приймач надає AUTO тільки
після dwell і перевірок. WASD — ручне перехоплення.
Готовий автономний запис — **Записи**, `03_auto_stop_takeover`.

Панель **«Активність мережі»** показує живі 306 компонентів `h` без
повторного обчислення мережі. Це знаковий rate-state, не спайки. Колір має
фіксовану шкалу індикатора ±0,1 (поза межами — насичений колір), з окремим
показом реальних min/max h; сітка є порядком індексів, не анатомічною
топологією. Поряд показано pitch/yaw мережі, координатора та реальний plant
input. Ці значення дозволяють відрізняти внесок мережі від супервізорів.
У старих replay внутрішній h не записувався — його показано як unavailable;
мережеві команди читаються з запису. MANUAL не анімує вигадану активність.

Цей observer доданий у snapshot поза захищеним runtime; controller/policy
виконується рівно стільки ж разів, як раніше. Для вже запущеного Python-сервера
потрібен перезапуск процесу, одного оновлення сторінки недостатньо.

1. **Наживо → Автономне → Старт**. Показати, що мережа отримує сенсори,
   формує команди й після admission керує рухом. Панель праворуч показує `h`.
2. Увести тривалість 300 с під час польоту. Годинник змінює ліміт на 5:00,
   фізична позиція та час продовжуються. Для огляду — камера **Зверху**,
   масштаб **Біля дрона** або колесо. Прапорець **Межа контакту** показує R.
3. Розгорнути **Сенсори, графіки та події**. Порівняти ToF та truth-зазор,
   Network, Coordinated, Accepted і Plant. Технічні деталі згорнути назад.
4. Вибрати **Ручне** або натиснути WASD. AUTO відкликається, ручний канал
   підтримує висоту. Відпускання клавіші не гасить горизонтальну інерцію.
   Для SHADOW вибрати **Ручне + SHADOW**. Газом користувач не керує.
5. Вибрати **Автономне** та **Новий старт**, якщо приймач уже відкликав AUTO.
   Створюється нова сесія; admission не обходиться. **Гальмувати / Space**
   у прийнятому AUTO вмикає/вимикає STOP. **Пауза** зупиняє simulation clock.
6. **Налаштування сцени**: змінити щільність, seed або стіну; натиснути
   **Нова сцена**. Підсумок показує фактичну площу й кількість об'єктів.
7. **Записи**: `03_auto_stop_takeover` відкривається після вибору. На 4,5 с
   показати ToF; на 6 с — STOP, на 8 с — ручне перехоплення. У replay радіус
   запису 10 см, у новому live — 20 см. Запис не змінюється через перемотування.
8. `02_shadow` демонструє preview без влади над фізикою; `01_manual` — інерцію.
   `04_denied_near_obstacle` — відмову AUTO при min ToF < 0,95 м.
9. Розгорнути **Модель і межі симуляції**: bundle/config identity та
   `mvp_admission.passed=false`, причина `broad_joint` (3/4).

Резервна демонстрація без live: усі п’ять записів доступні одразу після запуску.
Клавіші польоту не змінюють replay. У legacy `05_legacy_arena` повна матриця
ToF, roll/pitch та receiver evidence недоступні й так і позначені.

## Керування

| Клавіша | Дія |
|---|---|
| W / S | Pitch уперед / назад |
| A / D | Roll ліворуч / праворуч |
| ← / → | Yaw ліворуч / праворуч |
| M | MANUAL, відкликання AUTO |
| H | SHADOW; ручний канал керує фізикою |
| Enter | Запит AUTO через чинний admission |
| Space | STOP toggle лише під фактичним AUTO; інакше подія unavailable |
| P | Пауза / явне продовження |
| R | Нова сцена, повний reset, нова сесія |

Використано `KeyboardEvent.code`: WASD працює незалежно від української
розкладки. Текстові й числові поля не перехоплюються. Key repeat не додає
амплітуду, протилежні клавіші компенсуються. Горизонтальна амплітуда —
100 PWM, slew — 300 PWM/с за simulation dt. Нейтраль — 1500.
Після AUTO adapter відстежує фактичний RC anchor, тому перехоплення не
повертає давно застарілу ручну команду. Відпускання не додає velocity brake.
100 PWM — межа ручної цілі; якщо AUTO залишив більшу команду, перехоплення
успадковує її anchor та плавно повертає до ручної цілі з указаним slew.

Blur/visibility loss очищують клавіші й запитують паузу/MANUAL.
Окремий серверний heartbeat виявляє зниклого клієнта через 1,5 с wall time.
Продовження явне; AUTO приховано не відновлюється. Після відкликання
повторний AUTO потребує нової сесії за чинним receiver API.
Пауза зупиняє simulation clock, transport deadlines та watchdog у цій симуляції.

## Runner і власники стану

`demo/runner.py` — новий малий покроковий адаптер. Він використовує
`NavigationScene(engine='standalone')`, `SampleSchedule('multi')`,
`build_system(RunConfig.from_json(configs/mvp_runtime_v3.json))`,
`FlightSystem.tick`, `SessionReceiver`, `CommandPacket`, `observe_receiver`.
Великий `physical_case` не копіювався і не рефакторився.

Фізика завжди має dt=0,004 с, control/snapshot — 0,02 с. Один simulation
clock використаний сенсорами, FlightSystem і приймачем; offset mapping тут
не потрібний. Pacer виконує максимум п’ять фіксованих кроків за обхід;
довгі wall-clock затримки відкидає, без великого physics dt чи тривалого
catch-up. На повільній машині simulation time може йти повільніше wall time.

| Режим | Власник фізичного RC | Нейромодель |
|---|---|---|
| MANUAL | клавіші + окремий manual AltitudeHold | не виконується |
| SHADOW | та сама ручна гілка | preview, без lease |
| AUTO | лише чинний вихід SessionReceiver | pinned NumPy FlightSystem |

Manual altitude assist — окремий екземпляр існуючого `AltitudeHold` з
конфігурацією pinned runtime, без зміни його математики. Він оновлюється
один раз на фізичний tick за held capture-aligned range/attitude.
У AUTO його integral заморожений, а output anchor синхронізований із
фактичним plant throttle через `synchronize_output`. На takeover slew
починається з останньої застосованої команди.
Автономний AltitudeHold належить FlightSystem; `freeze_sync_v1` збережено.
Він оновлюється один раз на control tick у SHADOW/AUTO. На вході AUTO
перша issued команда точно дорівнює manual snapshot разом із throttle assist.

Доставка demo синхронна, у процесі, через справжній SessionReceiver.
**Модельований compute/link latency = 0**. Черг з відкладеною доставкою чи
мережевих fault-injection сценаріїв у першій версії немає. Receiver fallback
тут отримує ручну гілку; це не реалізація fallback G4. Власне фізичний
input завжди журналюється окремо від preview і факту прийняття команди.

Reset створює свіжі physics/PID, hidden state, координатор, обидва висотні
контролери, input adapter, сенсорні кеші/tracker і receiver із новою session ID.
Старий пакет відхиляється як session mismatch. Collision або invalid physics
завершують прогін. Для invalid physics UI залишає останній скінченний sample
та подію помилки; NaN не перетворюється на вигадану позицію. Прогін обмежений
заданою тривалістю 1–600 simulation seconds (початково 180) для обмеження пам’яті; записи зберігаються до нового reset.

## Записи та schema

`demo/recordings/` містить чотири нові `.json.gz` і один адаптований legacy
40-секундний прогін. Загалом близько 1,5 МБ. Історичне джерело legacy:
`data/diagnostics/watch_mvp_v2/arena_baseline_40s.json`; адаптована копія
самодостатня й не потребує цієї ignored папки після clone.

Новий schema — **`chong-fly-demo-v1`**:

- `manifest`: scene/geometry, seed, повна початкова поза й нульова швидкість,
  input bounds, dt, одиниці, конфігурація, hashes bundle/model/executed modules,
  hashes зовнішнього адаптера; snapshot provenance фіксується на reset.
- `input_schedule`: події, фактично застосовані на `step`/`time_s`, включно
  з автоматичною паузою/disconnect. Reset починає новий запис.
- `frames`: фізичні стан/clearance/collision, повні normalized ToF[64] та flow,
  capture timestamps/IDs/validity/age/new-or-held, request, actual authority,
  причини admission, receiver state/deadline, STOP та controller diagnostics.
- `trace`: незмінна семантика network/coordinated/supervised/issued/accepted.
  `trace.applied_pwm` лишається alias supervised. `accepted_pwm` — історичний
  факт конкретного issue через `observe_receiver`, не поточна дія lease.
  `receiver.accepted_pwm` описує чинний вибір на фізичному tick.
- `manual_pwm`, `plant_input_pwm`, `plant_source`: окремі команди та фактичний
  канал `manual/auto/fallback/terminated`. Відсутня команда — null.
- `events`, `end_time_s`, `yaw_bursts`: simulation time, завершення та існуючий
  `physical-yaw-bursts-v1` detector за реальною angular velocity, не PWM jumps.

ToF — normalized distance з max range 3,5 м. Стовпці зліва (+body Y) направо
(−body Y), рядки згори вниз. Invalid/unavailable не малюються як вільний простір.
Ground truth використовується лише для графіки/оцінювання.

Кнопка **Зберегти запис** ставить live на паузу й завантажує JSON через браузер.
**Свій JSON / GZ** відкриває записи demo schema. Для старих watch_mvp JSON
є Python `load_recording`/`save_recording`; готовий legacy вже в каталозі.
Непідтримуваний schema, некоректний час, координати, PWM або sensor payload
відхиляються з поясненням.

```powershell
.\venv\Scripts\python.exe -m demo --verify-examples
.\venv\Scripts\python.exe -m demo --verify-recording demo/recordings/03_auto_stop_takeover.json.gz
```

Перша команда повторно генерує чотири сценарії та вимагає точного збігу
всього запису в цьому самому середовищі. Друга повторно застосовує збережений
input schedule на первісних ticks і вимагає точного збігу чисельних frames.
Перемотування у UI лише читає запис; не запускає приховану симуляцію.
