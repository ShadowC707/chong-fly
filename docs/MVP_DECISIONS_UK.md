# Рішення поточного MVP

Дата: 2026-10-23. Це пояснення вибору, а не новий експеримент.

| Попередня ідея | Рішення і причина | Що збережено |
|---|---|---|
| Відтворювати «чемпіона» за гіперпараметрами з Optuna, з fallback і повторним навчанням | Завантажувати точний checkpoint: інша ініціалізація чи повторне навчання можуть дати іншу модель | `artifacts.research.load_research_run`, `evaluate.watch_mvp` |
| Після масштабування навчати W, обмежуючи лише її норму Фробеніуса | Для поточного кандидата заморожене все рекурентне ядро; однакова норма W не гарантує однакове згасання | Обидва режими дослідження, constraints і [звіт](../scripts/MVP_FROZEN_CORE_UK.md) |
| ONNX/C/quantization як запланований шлях експорту | Для MVP реалізований перевірений NumPy runtime. Три старі файли exporter були порожні, реалізації в них не втрачено | `edge.export_numpy`, чисельна перевірка, автономний release |
| Levy як обов'язкове дослідження кімнати | Вимкнено за замовчуванням: перевірені варіанти не дали однозначного виграшу покриття та зазору | Opt-in реалізація, факторні досліди й [звіт](../scripts/LEVY_FACTORIAL_V2_UK.md) |
| Буфер пам'яті як уже працююча просторова навігація k306 | Не заявляємо: відповідні входи обраної мережі відключені маскою | Модуль пам'яті та тести лишаються для досліджень інших конфігурацій |
| Isaac як необхідний поточний запуск | Поточний MVP перевіряємо standalone. Видалено лише launcher з чужим абсолютним шляхом | Backend та відповідний код симуляції не видалені |
| Реорганізувати всі Python-пакети | Зберегти робочі імпорти й точну ідентичність pinned коду; зараз реорганізуємо навігацію документації | Поточні API й сумісні re-export |

## Що підтверджено, а що ні

Заморожений `bridge_role_k306`, `tau_scale=0.25`, знаходиться в
`data/selection/mvp_frozen_core_v1/trial_00003/after`.
У попередньому досліді він мав напрямок 12/12, recovery 12/12 (максимум 0.40 с),
вузькі стимули 8/8 і сцени 7/7; широкі joint — **3/4**, не 4/4.
Це робочий дослідницький checkpoint, а не підтвердження польотної безпеки.

Структурний рефакторинг відтворив 8000 ticks до біта і 14 фізичних сценаріїв
без зміни чисельних траєкторій. Докази та обмеження наведено в
[інтеграційному звіті](MODULE_INTEGRATION_UK.md).

Очищення не змінює ваги, пороги, фільтри, модель сенсорів чи закони керування.
Справжній scheduler, сенсорні/мережеві/FC адаптери, прошивка fallback і перевірки
на обладнанні залишаються окремою роботою.
