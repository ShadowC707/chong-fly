# Chong-Fly: локальний демонстратор

Для живого польоту в Betaflight SITL + PyBullet див. [запуск і перевірку SITL](../docs/INTERACTIVE_SITL_UK.md).
Нижче описаний режим Standalone.

Із кореня репозиторію:

```powershell
.\venv\Scripts\python.exe -m demo
```

Відкрити **http://127.0.0.1:8765/** у сучасному desktop-браузері.
Вкладка **«Наживо»** → керування **«Автономне»** → **«Старт»**.
WASD не потрібні: свіжа сцена запускає pinned мережу, запитує AUTO через
чинний admission, далі прийняті команди керують фізикою. Панель МУХИ
показує 306 реальних станів `h` та команди до/після координатора.
Жива сцена за замовчуванням — кімната 8×8 м зі щільністю перешкод 20%.
Щільність 0–35% означає частку площі підлоги під випадковими перешкодами;
кількість визначається автоматично, обмеження 18 об'єктів у панелі немає.
Доступні «Скупчення та просвіти» й «Рівномірно», блоки, колони та перегородки
різних розмірів. Панель показує фактичні відсоток і кількість у створеній сцені.
Можна змінити щільність/seed, створити іншу розстановку або додати
стіну з центром X/Y, довжиною та напрямом 0°/90°. Геометрія застосовується
тільки до нового прогону. M — MANUAL одразу; Enter — запит AUTO після admission.
Готові прогони — у вкладці **«Записи»**. Вибір запису одразу відкриває його.
Налаштування сцени, докладні сенсори, графіки та події згорнуті за замовчуванням.
**«Зберегти запис»** розташовано у верхньому рядку відразу біля кнопки старту.
Камера й масштаб огляду обираються у двох списках над сценою.
Пауза відкликає AUTO через чинний приймач. **«Новий старт»** створює нову
сесію, якщо AUTO вже відкликано; ручну паузу можна продовжити.
Тривалість живої сцени — **1–600 секунд**, за замовчуванням 180 с. Її можна
редагувати під час польоту; новий ліміт має перевищувати час, що вже минув.
Зміни ліміту записуються у input schedule та точно відтворюються.
**«Межа контакту»** показує фізичну межу живого дрона (R = 0,20 м).
Діаметр — 40 см, мінімальний проміжок нової генерації — 48 см.
Старі записи відтворюються зі своїм записаним радіусом (10 см).
Видимі корпус і пропелери вкладаються в неї; перший контакт завершує прогін.
Нові живі прогони використовують точну перевірку сфери на всьому фізичному
кроці: біля кутів боксів і країв циліндрів зайва прямокутна зона не зупиняє дрон.
Версія перевірки записується як `contact_model: sphere-sweep-v1`.
Наближення для огляду — колесом над сценою.
Якщо сервер уже був запущений до оновлення коду, його слід перезапустити.
Потрібне вже встановлене середовище проєкту; нових Python/JS залежностей немає.
Сервер слухає тільки `127.0.0.1`. Зупинка — Ctrl+C у вікні запуску.

Повна [інструкція для захисту, формат запису та перевірки](../docs/INTERACTIVE_DEMO_UK.md).
Окреме [питання чинного контракту відкликання](../docs/INTERACTIVE_DEMO_CONTRACT_NOTES_UK.md).
Підсумкові hashes та evidence: [verification.json](verification.json).

Записи у `recordings/` працюють без інтернету. UI assets — у `web/`, без CDN.
Параметр `--port 8766` дозволяє використати інший локальний порт.

```powershell
.\venv\Scripts\python.exe -m demo --verify-examples
.\venv\Scripts\python.exe -m demo --verify-recording demo/recordings/03_auto_stop_takeover.json.gz
```

`--record-examples` створює записи лише за відсутності відповідних файлів
(exclusive create). Не перезаписує перевірені артефакти мовчки.
