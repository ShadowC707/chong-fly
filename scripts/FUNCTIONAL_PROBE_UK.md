# Перший функціональний дослід k306

Це експеримент із **вже навченою мережею**, не scripted-керування дроном.
Фізика, польоти, нове навчання та Optuna не запускаються. Вимірюємо реакцію
конкретних збережених ваг на задані показники сенсорів та тимчасові втручання.

Питання першого циклу: **чи впливає LT51 на відповідь yaw у цьому кандидатові?**
Цю клітину обрано через раніше знайдений анатомічний маршрут від LPLC2 до
сакадного виходу. Це мотивація перевірки, а не доказ її функції.

## Запуск

Із кореня проєкту:

```powershell
.\venv\Scripts\python.exe -m optimizer.functional_probe --research-only
```

За замовчуванням завантажується `data/selection/registry_mean_spatial_v1/trial_00001`:
кандидат `bridge_role_k306`, 30 епох попереднього навчання, seed 42,
кодування `proximity-mean-v1`, режим `masked` зі збереженням припущених знаків.
Це дослідницький кандидат, який не пройшов попередній функціональний допуск.
Вибір не означає, що він є переможцем або біологічно доведеною моделлю.

Потрібні локальні `checkpoint.pt`, `report.json` та каталог `graph` цього запуску.
Чужий checkout без ваг не зможе відтворити експеримент лише за цією командою.
Завантаження перевіряє хеш ваг, metadata та чинний контракт моделі; несумісні
ваги не підміняються випадковими і не мігруються мовчки.
Використовуються CPU й один обчислювальний потік. Для графіків потрібен
`matplotlib` із `requirements-experiments.txt` (у поточному venv встановлений).

Результати зберігаються в новій папці `data/diagnostics/functional_probe_<час>`.
Шлях друкується наприкінці. Існуючі результати не перезаписуються.

## Що саме подається на вхід

Один випадок вільного простору й вісім стимулів:
ліва/права сторона × нормалізована відстань 0.1/0.2 × ширина 1/4 стовпців ToF.
У поточному контракті дальності це 0.35/0.70 м. Усі вісім рядків обраних
стовпців мають однакову відстань. Це статичні синтетичні сигнали ToF,
**не біологічна ретинальна картина наближення об'єкта**.

Кожен випадок триває 3.5 с: 1 с вільного простору → 0.5 с стимулу → 2 с
відновлення, із кроком 20 мс. Початковий прихований стан нульовий, flow=0,
memory=1; пам'ять у цьому кандидаті від'єднана. Прогрів 1 с фіксований і
не є доказом досягнення стаціонарного стану для будь-якої іншої моделі.

## Що вимикається

План `configs/functional_probe_v1.json` задає групи точними анотаціями:

| Варіант | Мета |
|---|---|
| intact | Початкова мережа |
| looming_input | Блокування 210 вхідних клітин LPLC2 як перевірка сенсорного інтерфейсу |
| yaw_readout | Блокування чотирьох клітин, із яких читається yaw |
| lt51 | Блокування одного кластера LT51, предмет гіпотези |
| matched_control_1…3 | Три відтворювано обрані контрольні втручання |

«Блокування» означає, що після **кожного** кроку інтеграції стан обраного
кластера встановлюється в нуль перед декодуванням і наступним рекурентним
кроком. Воно починається з прогріву та діє до кінця. Це блокування стану,
а не видалення окремого ребра; фізіологічну оптогенетику воно не відтворює.
Ваги не змінюються. Перенавчання між втручаннями немає. Наприкінці intact
повторюється; виходи та всі стани повинні збігтися побітово.

Контрольні групи мають той самий розмір кластерів, сторону й припущений
вихідний знак, але не належать до сенсорного/моторного інтерфейсу чи цільових
груп. Контролі **не** вирівняні за кількістю/силою зв'язків. Три контролі
не дають статистичного висновку про унікальність LT51.

Індекси та точні root IDs зберігаються в `clusters.json`; для редукованих
моделей один індекс може означати кілька клітин. Відсутня група зупиняє
експеримент, а не перетворюється на мовчазне «вимкнення нічого».

## Як читати результат

Відкрий `responses.png`:

1. Верхні графіки — yaw для близької широкої перешкоди зліва/справа.
   З кожного варіанта віднімається **його власний** запуск без перешкоди
   в ті самі моменти часу. Так відділяємо зміну базового виходу від
   відповіді на стимул. Позитивна команда означає поворот вправо.
2. Нижня теплова карта — різниця станів intact між лівим стимулом і вільним
   простором. Колір означає зміну модельного стану, не знак синапсу й не
   виміряну частоту спайків. Номер рядка можна знайти в `clusters.json`.
3. Стовпчики — середня викликана відповідь yaw за 0.5 с лівого стимулу.
   Це не миттєвий PWM, не кут повороту й не оцінка безпеки.

`report.json` містить усі вісім стимулів плюс clear, амплітуди, зміни відносно
intact, порогову затримку/відновлення, точний план, версії та хеші.
Поріг 20 PWM потрібен лише для опису часу відповіді, не для допуску.
Затримка рахується за індексом першого надпорогового post-step відліку:
нуль означає вже перший відлік, а не миттєву біологічну реакцію.
Відновлення — перший відлік, після якого відповідь залишається в межах
порога до кінця спостереження; `null` означає, що її не виявлено/не дочекалися.

`traces.npz` зберігає всі стани й чотири виходи для всіх варіантів:
`states[втручання, стимул, час, кластер]`,
`pwm[втручання, стимул, час, канал]`, точні входи та час post-step відліків.
Порядок варіантів і стимулів заданий у звіті. Throttle тут — placeholder,
контролер висоти не запускається.

## Перший отриманий результат

Для близької широкої перешкоди зліва:

| Варіант | Середня викликана відповідь yaw, PWM |
|---|---:|
| intact | 223.66 |
| looming_input | 0.00 |
| yaw_readout | 0.00 |
| lt51 | 200.29 |
| matched_control_1: CB0344 | 223.66 |
| matched_control_2: LHAD1g1 | 223.66 |
| matched_control_3: PVLP015 | 208.53 |

У цій моделі блокування LT51 змінює відповідь, але не знищує її.
Ефект має й PVLP015. Не можна робити висновок, що LT51 унікально необхідна,
або переносити ефект на живу муху. Нуль від блокування інтерфейсних груп
очікуваний за нашим маршрутизованим кодуванням/декодером і не доводить
біологічної правильності цього інтерфейсу.

Це розвідувальний набір: він уже використаний для аналізу і не є незалежним
тестом якості. Подальша зміна гіпотези має отримати новий план/каталог.
Наступний змістовний крок — порівняти LT51 та PVLP015 на всіх зафіксованих
стимулах і перевірити їхні виміряні входи/виходи, перш ніж додавати нові групи.
Змінені гіпотези згодом перевіряються на окремих відкладених сценаріях.

## Інші кандидати

`--run` задає інший сумісний bundle, `--config` — інший план груп,
`--out-dir` — новий каталог. Сам сценарій стимулів поки версіонований у коді;
це свідомо обмежений перший протокол, не універсальний редактор експериментів.
Не всі кандидати мають потрібні групи: для іншого сімейства слід окремо
обґрунтувати план. Успішний запуск не змінює `training_ready`.
