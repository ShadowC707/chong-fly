# Перше заняття: рух → гальмування → огляд → рух

Питання експерименту: чи дозволяють поточні фізика, стабілізація та
зворотний зв'язок за optical flow виконати заданий огляд із малим дрейфом?
Це контрольний сценарій із явним розкладом фаз. Він не завантажує
конектому, не навчає модель і не визначає самостійно, коли потрібно оглядатися.

## Запуск із кореня проєкту

```powershell
.\venv\Scripts\python.exe -m scripts.scan_probe
```

Це 10 секунд симульованого часу на CPU; Isaac і CAVE не потрібні.
Кожен запуск автоматично створює новий каталог у `data/diagnostics`.
Наприкінці команда виводить його повний шлях. Усередині:

- `trace.png` — графіки для першого перегляду;
- `report.json` — параметри, результати фаз, стан завершення, версії та хеші коду;
- `trace.csv` — запис кожного фізичного кроку для детального аналізу.

На цьому комп'ютері бібліотеку графіків уже встановлено в `venv`.
На іншому комп'ютері після основних залежностей проєкту:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-experiments.txt
```

## Що відбувається

| Час | Фаза | Команда |
|---|---|---|
| 0–2 s | move | Рух уперед із демпфуванням optical flow |
| 2–5 s | brake | Прибрана крейсерська складова; flow гасить залишковий рух |
| 5–7 s | scan | Демпфування flow триває; yaw отримує +80 PWM |
| 7–10 s | resume | Нейтральний yaw, відновлення руху вперед |

Перед scan норма flow має бути ≤0.05 протягом останніх 0.2 s за
спостереженнями контролера. Інакше вмикається `blocked`, лишається
демпфування, scan/resume не виконуються. Це перевірка готовності на вході
у scan, не повна система аварійного захисту чи ручного перехоплення.

Нижній дальномір і attitude керують throttle через існуючий `AltitudeHold`.
Навігаційна частина бачить optical flow. Координати й справжня швидкість
симулятора використовуються тільки для вимірювання результатів.
Кімната порожня, 8×8 m, цільова висота 1 m; початкова швидкість 0.6 m/s.

## Як читати графік

1. **Horizontal speed:** швидкість повинна знижуватися у brake,
   залишатися малою у scan і зростати у resume.
2. **Yaw:** зміна кута має відбуватися переважно у scan. +80 PWM — це
   команда швидкості повороту через контролер, а не вимога повернутися на 80°.
3. **Height:** перевір масштаб осі! Крива може виглядати хвилястою,
   хоча весь діапазон коливань становить міліметри.
4. **Trajectory:** видно пряму ділянку, місце уповільнення/огляду й новий напрямок.
5. **Pitch/Yaw command:** це фактично прикладені команди; зміна команди
   передує фізичній реакції.

У таблиці `max drift` — максимальне горизонтальне віддалення від точки
початку відповідної фази, не тільки різниця між початком і кінцем.
Під час move/resume це звичайне переміщення; для scan це цікавий нам дрейф.
`height error` виміряна від 1 m. Кут у таблиці й на графіку правопозитивний;
сире `yaw_rad` у CSV зберігає лівопозитивну FLU-конвенцію симулятора.

`new heading sectors` рахує нові напрямки центральної осі сенсора у восьми
секторах. Це грубий показник напрямків огляду, не побудована карта,
не доказ збирання нової інформації й не використання ring memory у плануванні.

## Твій перший запуск

Перед запуском запиши три очікування: де падає швидкість, де змінюється
курс і чи відновиться рух. Після запуску відкрий `trace.png`, знайди ці
ділянки й звір їх із таблицею. Код поки читати повністю не потрібно.

Другий запуск — один контрольований контраст: прибрати поворот,
залишивши решту параметрів і seed такими самими:

```powershell
.\venv\Scripts\python.exe -m scripts.scan_probe --yaw-offset 0
```

Тут фаза scan означає паузу без повороту. Порівняй кут і дрейф з першим
прогоном. Однаковий seed відтворює початкову випадковість; при зміні
команд рух і сенсорні спостереження закономірно відрізнятимуться.

За потреби інший seed задається `--seed 43`. Змінюй один параметр за раз.
Пороги допустимого дрейфу, висоти й прогресу ще потрібно узгодити;
скрипт вимірює результат і не видає маневру автоматичний допуск.

## Де дивитися код

У `scripts/scan_probe.py`: `ScanProbePolicy.step_np` задає команди;
`RecordingEnv` записує траєкторію; `phase_metrics` обчислює показники;
`plot_trace` малює графіки. Фізичний цикл виконує існуючий
`optimizer.rollout.simulate_policy_rollout`.
